# 能力选择与环境预检

每次上传先确定两件独立的事：在哪个浏览器会话登录，以及通过什么通道提交。沿用宿主工具的说明和权限边界；技能不要求固定浏览器 ID、扩展或未公开接口。

## 选择顺序

| 维度 | 首选 | 降级条件与说明 |
|---|---|---|
| 浏览器环境 | 宿主内置浏览器 | 若不支持网站登录、页面控制或本地文件选择，说明缺项，再使用可连接的外部浏览器；新会话可能需要成员再次登录 |
| 配置提交 | 当前已验证的连接器/API/WebMCP | 确认覆盖字段、鉴权、版本控制、保存和回读语义；无合适接口则使用页面 JSON |
| 批量配置 | 页面提供的 JSON 编辑/导入 | 先读当前对象、合并差异、校验、提交、回读；超出覆盖范围的板块保留独立操作 |
| 表单兜底 | DOM/可访问性语义操作 | 先证明代表性字段确实保存；图形点击只用于无语义入口的必要步骤 |

已有可用批量入口就直接利用，不为寻找更低层接口反复探测。页面没有 WebMCP 不代表没有 HTTP API；网络中出现端点也不证明适合稳定复用。只有获得当前接口文档/声明与受支持的鉴权方法时才接入，不猜请求结构或从浏览器导出凭证。平台校验错误必须解决，不能换通道绕开。

## 写入前的最小预检

1. 发现工具与浏览器，核实固定站点及本人登录；列出本轮所需操作并记录实际通道。内置浏览器满足本轮能力时沿用其会话。已打开外部窗口不构成切换理由。确需切换时，先记录具体缺项，再读取账号、Agent/Scenario ID 和最新配置版本；放弃前一会话的保存基线。
2. 阅读宿主文件上传文档，确认它支持本机绝对路径或规定的临时文件传递机制。检查真实上传控件是否支持多选；不能因有文件控件就宣称自动上传可用。
3. 通过下方包预检后，以第一份实际待上传文档验证路径，按 [知识库上传与恢复](workflow.md#知识库上传与恢复) 回读。它计入正式清单。只读审查只能标“工具支持、端到端待验”。
4. 检查当前页面是否有 JSON/导入入口，读取已保存结构和可见校验限制，明确独立的 Profile、知识、场景保存边界。完成这些之后再进行大量表单操作。

只有缺少必要能力才要求准备环境。说明模板：

> 当前宿主可以控制页面，但不能把本地文件传给上传控件。配置文本仍可批量写入；模板文档上传需要连接支持文件选择的浏览器。建议先启用宿主的上传能力；若不可用，再连接外部浏览器。该外部工具若要求扩展或本地文件权限，我会说明实际要求并取得授权。

不要把某一次 Chrome 的“允许访问文件网址”提示当作所有环境的安装要求。优先减少安装；新权限按宿主审批处理。切换浏览器需重新核对账号与目标。

## 配置包预检

先运行 `python -c "import sys; print(sys.executable); print(sys.version)"` 验证解释器实际启动。Windows 若命中商店占位符或启动失败，试 `py -3`，或用宿主明确提供、可访问包目录的 Python 绝对路径执行同一探测。找不到可用解释器时，报告命令和错误，提示安装 Python 3 后重试。

用同一个解释器执行 `scripts/preflight.py`，脚本和包路径均用绝对路径并正确引用。读取退出码和 JSON。

| 结果 | 写入条件 |
|---|---|
| 退出 0 且 `status: OK` | 继续人工核对及目标基线检查 |
| 退出 1 且 `status: REVIEW`，`errors` 非空 | 停止写入。报告具体错误与源文件；缺规则/动作表时交回生成侧补齐 |
| 退出 1 且 `status: REVIEW`，`errors` 为空且 `pending` 非空 | 逐字段记录当前平台证据、采用值及业务依据。独立且明确授权的板块可执行；有未解决待核项时停止依赖写入和发布 |
| 解释器/脚本启动失败、`status: ERROR`、输出缺失或退出码与结果不符 | 停止写入，报告具体失败。手工检查可定位问题，预检仍需实际运行 |

## 已验证的范围（2026-11-25）

| 证据 | 结论 | 边界 |
|---|---|---|
| Codex 内置浏览器实际上传 | 4 份模板 MD 完成上传和处理，无额外扩展 | 仅证明当次宿主与站点；其它 Agent 未逐一实测 |
| 页面 JSON 只读核对及此前保存回读 | 编排 schema_version 为 `2`，61 项编排和 2 条规则可存取 | 61 是案例数量，不是新上限 |
| 场景 JSON 顶层字段 | `live_programme`、`interaction_workflows`、`live_script_md`、`live_script_entries`、`live_audience`、`context_routing` 等 | 文件上传、Profile、状态/发布元数据仍按各自保存入口处理 |
| 页面工具发现 | 当次无 WebMCP 工具 | 没有验证可直接调用的 HTTP API |

平台升级、登录变化或工具失效后重新确认受影响能力。不要每个字段重复发现工具；重用有效会话和已读文档。
