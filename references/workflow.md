# 控制台执行与恢复

依据 Native 手册 §3–11、16–18 与既有上传会话的操作观察（2026-11-24 汇总，非当前站点全路径再验收）。页面标签可变，使用当前页面提供的真实控件。只允许工具支持的文件选择/上传，不伪造上传路径或用自造接口绕过登录。

## 执行顺序

1. 登录后读取当前 Agent/Scenario 列表与目标身份。新建先搜索同名；更新按实际 ID 定位。创建请求超时先刷新列表确认是否已成功，避免重复创建。
2. Profile：填写名称、Soul、Agents，点击 Profile Save。重新加载后逐项比对；记录实际 Agent ID 和可见版本。避免把本场长编排塞入长期人设。
3. Scenario：创建或选择指定的单个 Live 场景，记录真实 Scenario ID。新建准备期间 draft；只在已授权完成条件满足时 active。现有场景不为方便擅改状态。填写名称、场景指令、语言及记忆/知识等，保存再回读。
4. 知识：选择正确库/领域（需新建且授权时才创建），上传正式模板 MD。等待任务状态为处理成功，再核对类别/预览。已存在同名文档先比较，不盲目重复导入或删除。数字人原视频由使用者在其执行端登记；别名未登记单列缺口。
5. Live configuration：按包设模式、正文结束/循环、语言/节奏、LiveScript。常规 v0.3.1 是手写正文：不点击 Prepare content 覆盖正式稿。Prologue/LiveMat 仅在源包有明确配置时使用，更新不清空已有值来凑格式。Save 后回读原稿，用实际保存文本核对非空行。发现规范化/换行差异先重新算范围并记录源稿差异，不能沿用过期行号。
6. Programme orchestration：按索引顺序逐项；先类型，再来源、行范围、类别、结束条件、切换方式、口型、评论开关、时间/配额和过场。切类型会重置默认，逐个重新填写。Apply element 写回编辑器，Live configuration Save 才保存。脚本变化需刷新引用/source_hash；回读完整顺序而不只看最后一项。UI 循环编号从 1 起；不要把内部 0 起且末端不包含的边界直接填到 UI。
7. Audience comment selection：单独填写队列、拒绝/接受关键词、未决 LLM 策略、容量/过期。启用 LLM 判断至少有一条接受/拒绝规则。拒绝优先；不能以互动工作流的冷却替代队列设置。
8. Rules of interaction：按规则表顺序建/更新，填触发、条件、即时确认、Timing、每一个有序动作、Completion/Failure/冷却/过期。字段适用性按 mapping.md。Apply workflow 后保存规则；重开检查启用数、顺序和全部动作。未要求的规则不新增；旧规则删除必须在本次范围中，不能默认清除。
9. 汇总回读各组，再按已批准目标保存 active，核实 published revision。新建对象或文档不是事务：失败留下哪些已保存项须明确，不假称全部回滚。

## 状态与恢复

| 状态 | 操作 |
|---|---|
| Apply 成功 | 只视为编辑器更新，继续对应板块 Save |
| 未保存关闭确认弹窗 | 留在/返回编辑器，保存并回读后再关闭；不盲点丢弃 |
| Partially saved | 记录成功组 identity/runtime/speech_language/audience；重开比较失败字段，仅修失败组 |
| 版本冲突 | 重新读取最新版本，比较用户并发改动；非重叠变更可在范围内重施，重叠语义冲突问用户，不能强覆盖 |
| 请求超时/无结果 | 先重新加载查是否已生效，再决定重试，尤其创建和导入不能重复提交 |
| 登录过期 | 保存非敏感进度事实，交还用户重新登录；回读目标 ID 后恢复 |
| UI/字段变化 | 重新观察并与文档对照，不能猜选择器、枚举或换控件完成“看起来相似”的功能 |

相同故障经一次回读和针对性修正仍重复，停止该依赖链并报告明确缺口；不要无限重试或用完整 JSON 覆盖来绕开错误。独立且已经授权的板块可继续，但整体发布必须满足预期。记录结构保留本地 ID→后台 ID 对应与完成状态，不存完整敏感后台快照。
