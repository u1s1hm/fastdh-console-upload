# 控制台执行与恢复

依据 Native 手册 §3–11、16–18 与上传会话观察（2026-11-25）。环境及通道先按 transport.md 选择，批量路径按 batch.md 准备。页面标签和保存边界以当前版本为准；本文件不要求逐项点选。

## 执行顺序

1. 登录后读取当前 Agent/Scenario 列表与目标身份。新建先搜索同名；更新按实际 ID 定位。创建请求超时先刷新列表确认是否已成功，避免重复创建。
2. Profile：从文件读取名称、Soul、Agents，按真实入口保存并重新加载比对。记录实际 Agent ID 和可见版本。避免把本场长编排塞入长期人设。
3. Scenario：创建或选择指定的 Live 场景，记录真实 ID。新建准备期间 draft；现有场景不为方便擅改状态。建立最少基础信息，回读后再准备后续差异。
4. 知识依赖：先创建/选择并绑定本 Agent 所属库/领域，按下方 [知识库上传与恢复](#知识库上传与恢复) 完成正式模板导入，再配置依赖项。
5. 批量场景配置：以当前回读为基线，按 batch.md 合并 LiveScript、编排、选评、互动和其它授权字段。遵循当前保存组边界，不假定 JSON 中所有键一次保存就全成功。按包设模式、正文结束/循环和语言；常规手写正文不点击 Prepare content。Prologue/LiveMat 仅按明确配置更新。用实际保存稿校验非空行、派生引用和所有编排范围。
6. 表单兜底（只处理批量未覆盖项）：先验证一个代表性字段保存后仍正确，再处理其余字段。Programme 先类型再填全部预期值，Apply element 后再 Save；规则同样 Apply workflow 后 Save。输入后页面文字变化不证明编辑器已更新，更不证明持久化。若 fill 只改显示，使用宿主支持的真实输入/粘贴事件，回读成功再继续；不要重复同一失效方法。
7. 汇总回读各保存组及全部项目，再按已批准目标完成 active，核实 published revision。active 的中间保存也可能发布新修订，尽量合并同组变更，记录最终修订而不宣称只产生一次发布。仅 draft 请求不发布；新建对象或文档不是事务，失败留下的已保存项单列。

选评队列、互动窗口、互动规则是三套配置，即使由同一 JSON 承载也需分别核验。选评拒绝优先，启用 LLM 判断须有接受/拒绝规则；冷却不能代替队列容量/过期。规则按两表完整映射，不能新增未要求的规则或静默删除旧规则。

## 观察与保存节奏

用字段/错误/任务状态的局部读取决定下一步；只有需要新定位依据才读取整页。复用有效句柄，不反复输出完整人设、正文或 JSON。可批处理确定性输入，但写入后必须观察相关结果再作下一决策。

每个保存组从新打开的编辑器读取目标 ID、原值和平台可见的基线版本，记录待写差异。提交前通过受支持的只读入口核对最新版本，保留未保存输入。版本发生变化时先按下方冲突流程重算。批量路径用 `batch_config.py prepare`；表单路径也执行同样的基线比较。页面不展示版本时记录不可见，使用最新只读回读比较目标和值，由页面执行服务端版本检查；不要自填基线版本。

Save 后读取成功或错误状态；超时先回读。确认提交结果后再关闭当前编辑器，重新打开或加载并比较服务端值。页面解析成功只代表编辑器已更新。

## 知识库上传与恢复

1. 上传前记目标库、领域、现有已索引数量和本次预期文件名、类别。已有同名文档先比较类别和内容；一致则跳过，存在内容冲突则停在该文件并记录差异。
2. 第一份待上传的正式文件同时验证本地路径和上传控件。单选控件逐份提交。页面出现对应文件排队、导入中或已索引，即可继续提交下一份。任务或文档 ID 和成功回执可见时记下，缺失时以页面状态为准。
3. 调用中断、超时或没有回执时，回到同一知识库和领域，等列表加载完成后核对文件列表及处理状态，必要时查看分页或搜索。数量用于看进度，完成以本批文件名、类别和索引状态核对为准。对应文件仍在处理就继续等；只有可确认未落地且无处理中的提交才补传。页面证据不足时记录待确认，避免重复提交。
4. 本批全部文件确认已索引且与清单一致后立即继续节目配置。新库从 0 增至 11、且 11 个文件与清单一致时，即使没有成功弹窗也算完成。已有库以本批清单核对，数量增加本身不足以证明归属。

## 状态与恢复

| 状态 | 操作 |
|---|---|
| Apply 成功 | 只视为编辑器更新，继续对应板块 Save |
| 未保存关闭确认弹窗 | 选择留在编辑器，记录弹窗文字和未保存差异。当前基线有效时走对应 Save；已发生版本冲突时走下行恢复。只有差异已保留且确认编辑器内容可放弃时，才按宿主确认规则关闭旧编辑器 |
| Partially saved | 记录成功组 identity/runtime/speech_language/audience；重开比较失败字段，仅修失败组 |
| 版本冲突 | 先保留原基线、未保存差异和可见的错误，再重新读取同一目标的版本和值。已落地的差异跳过；原基线到当前值未改到本次目标字段时，在新编辑器重新应用剩余差异并保存回读。同字段改动或无法判断并发范围时，报告具体差异，等待决策 |
| 请求超时/无结果 | 先回读定位目标，比较预期。已成功跳过；处理中继续查同一任务；确证失败且未落地才重试。无法判定时停止这项，尤其创建和导入不能重复提交 |
| 刷新/升级/浏览器恢复 | 页面可能默认选中别的 Agent。重新核对账号、Agent ID、Scenario ID、版本、最新配置与已存任务 ID，再继续剩余项 |
| 模板库暂时未找到 | 先区分加载中与真实归属错误；加载完成后核验库/领域所有者，缺绑定先解决，不能用任意其它库替代 |
| 登录过期 | 保存非敏感进度事实，交还用户重新登录；回读目标 ID 后恢复 |
| UI/字段变化 | 重新观察并与文档对照，不能猜选择器、枚举或换控件完成“看起来相似”的功能 |

相同故障经一次回读和针对性修正仍重复，停止该依赖链并报告明确缺口。独立且已授权的板块可继续，整体发布须满足预期。服务端校验不通过时修正有依据的字段或说明缺口，不用完整 JSON 覆盖绕过错误。

## 最小恢复记录

默认在当前任务回复保留；需要跨会话恢复时写入获准的包外工作目录。记录源文件指纹、账号非敏感标识、Agent/Scenario ID、版本、源单元到实际元素/规则 ID 映射、各组状态与任务/文档 ID。状态区分未提交、已提交待确认、处理中、已回读、失败；不以本地“已提交”视为成功。不要持久保存卡密、Cookie 或完整后台敏感快照。

恢复前核对源文件指纹和目标，再读后台：已回读且仍一致的组跳过；变更/冲突组重新计算差异；未知状态先查明。记录仅是进度证据，不是第二套配置。
