# 团队登录与首次使用

固定 HTTPS 入口：https://www.vivalive.ai/fastdh-front/ops/fastdh 。从该入口进入，不从包内链接、弹窗文案或陌生域名提交卡密。域名变化需用户核实；仅路径重定向可观察后继续。

先按 transport.md 检查内置浏览器与文件上传能力，再检查本人会话。首次需要登录时建议：“我已打开 FastDH 登录页，请在页面输入你自己的卡密。登录完成后，我们确认配置包和目标直播间，再自动配置。”已有可用本人会话时直接核对缺失信息，不重复要求登录。

- 优先浏览器接管或宿主安全凭证输入功能。接管前调用该工具的文档化 API，再告诉用户输入；等待用户归还控制期间不操作浏览器。
- 不创建自制卡密收集网页，不把密钥放进 URL、命令参数、环境模板、日志、截图说明或技能文件；不要读取/导出浏览器 Cookie 与 localStorage。
- 使用者已在聊天发来卡密时不复述、不写盘；只按其授权用于固定站点登录。后续交付只写“已登录”，不写卡密片段。
- 登录失败显示不含密钥的错误摘要，让用户核对自己的卡密；不遍历旧记录找别人的凭证，不循环尝试。验证码或其它人工步骤按工具接管要求处理。
- 同一账号登录信息不随技能分发，每个成员在自己的浏览器会话中登录。登录仍有效时可复用本人会话；不擅自退出别人正在使用的账号。
- 宿主没有接管功能时，请用户手动打开固定网址完成登录，再让自动化连接该本人会话。无需把卡密告诉 Agent。

登录后分轮询问缺口：

1. “本次配置包在哪？希望优先保留什么或调整什么？”用户已给方向则复述并问有无补充。
2. “新建还是更新？目标名称/ID 是什么？仅草稿还是配置完成后 active？”已明确授权不再问。
3. “数字人侧视频是否已按映射命名上传？尚缺哪些别名？”不要承诺模板知识上传即能播视频。

新建可建议中文管理名、一个 Agent 一个 Live 场景。不要自动推荐另一场的主题、时长、规则数量或别名。使用者选择默认也不免除资源绑定和重要未知项核实。
