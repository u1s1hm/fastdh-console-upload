# 批量准备与校验

在当前页面存在批量入口时读取本文件。批量减少网络/控件操作，内容核验仍覆盖全部条目。源包是业务依据，最新服务器回读是保留值与版本依据。

## 准备一份有来源的差异

1. 直接读取正式文件，记录字节 SHA-256；只为比较统一 CRLF/LF，保留空行、标点和正文。保存文本若被平台规范化，以回读稿重算非空行并校正范围；原稿不改。源文件指纹未变不能证明远端正文一致。
2. 记录目标 Agent ID、Scenario ID、当前版本/revision，以及现存配置。用当前界面/文档证明字段结构。例：当前编排 `live_programme.schema_version = "2"`；新增元素 ID 已观察到要求 `lpe_` 加 32 位小写十六进制。其它 ID/哈希的算法不能照抄推断。
3. 将本场索引按顺序映射到元素，将两张互动表映射到有序规则/动作。缺字段保留；EMPTY/clear 转成该字段实际支持的空值；N/A 不写；未解决的 PENDING 阻断依赖项。若当前证据已解决平台疑问且业务意图明确，在包外变更单记“源字段→采用值→依据”，不修改原包。预检仍可能报告历史标记 REVIEW，不可伪称原包无待核；平台证据不能代替缺失的业务选择。原始占位符不直接发送。
4. 更新已有数组时，从最新数组按实际 ID 修改单个对象，保留未知键与未授权删除的条目。整段数组替换必须检查全部项目；局部修改不能只传一条列表造成其它项目消失。无规则的新建场景写空列表；更新时仅在明确清空范围内移除规则。
5. 记录源单元 ID → 后台 ID 映射。已有元素复用 ID；新元素只在已证实格式下分配一次，重试沿用。刷新后的实际 ID 优先于本地候选。规则 ID、媒体 ID 和知识 ID 不使用节目 ID 格式代替。
6. 校验类型、数量、顺序、非空行范围、配置备注排除、模板类别、结束条件、口型、评论、规则/步骤数量及启用。循环边界按已证实的 UI/JSON 表达换算，不能猜末端是否包含。`source_hash` 等派生值沿平台机制更新并回读；不知道算法时不能编造哈希充数。

当前上限只采用当前 schema、手册或服务端明确校验给出的值，并记录依据。历史 50 项拒绝和后来 61 项成功都不是永久上限；未知就标未知，遇到验证拒绝停止该提交，不分拆来偷偷改变节目语义。

遇到非 schema 2 的既有场景时，本工具会提示待核；保留旧场景并按当前受支持的界面处理，不为通过本地检查强制升级结构。新 ID 可用 `batch_config.element_id(实际场景ID, 源单元ID)` 得到稳定候选，但已有映射/实际 ID 优先，不能按候选重新编号旧元素。

## 本地工具

`scripts/batch_config.py` 是标准库离线工具，不登录、不发请求、不直接解析任意自然语言包为平台配置。Agent 负责按上面的映射准备数据，它负责确定性合并、保留检查、范围验证及回读比较。

临时输入格式（只放获准的包外工作目录，不提交仓库）：

```json
{
  "target": {"agent_id": "实际Agent ID", "scenario_id": "实际场景ID"},
  "baseline": {"target": {"agent_id": "实际Agent ID", "scenario_id": "实际场景ID"}, "revision": "已回读版本", "config": {}},
  "current": {"target": {"agent_id": "实际Agent ID", "scenario_id": "实际场景ID"}, "revision": "提交前回读版本", "config": {}},
  "changes": {},
  "replace_arrays": [],
  "delete_ids": [],
  "checks": {"categories": [], "spoken_lines": [], "max_elements": null}
}
```

- `changes` 为已解析的实际值；对象递归合并，数组只在 `replace_arrays` 明列 JSON 路径后替换（包含 `/interaction_workflows/0/steps` 等嵌套数组）。遗漏保留，标量字段 `null` 是显式清空，不是继承；合法性仍须当前平台核实。工具拒绝把现有对象/数组整体改成 null，以免绕过保留检查。
- `checks.categories` 来自本场资源映射，`spoken_lines` 是正式上线稿允许的口播非空行号；配置备注不能加入。`max_elements` 未知用 `null`，已知填整数并在变更单写依据。
- 删除既有节目/规则 ID 时须在 `delete_ids` 明列；这仅落实用户已授权范围，工具参数本身不授予删除权限。
- `current` 必须来自提交前的新回读。版本或配置不同会停止并要求重新比较，工具不自动覆盖并发改动。通过之后仍需平台版本校验，不能消除读取至保存之间的竞态。

```bash
python scripts/batch_config.py prepare /absolute/work/input.json > /absolute/work/prepared.json
python scripts/batch_config.py compare /absolute/work/expected.json /absolute/work/readback.json
```

prepare 输出包含 `config`、变更路径和校验结论。**只把 `config` 按页面支持的格式提交**，不上传整个工具信封。非零退出码时查看问题，不提交。没有变更时跳过保存。compare 两个文件均使用 `{ "target": ..., "config": ... }`，比较正式正文只容许 CRLF/LF 差异；其余差异报告到路径，避免把正文或敏感值打印进日志。

局部更新的 expected 只列本次应核验的顶层字段；提交前的基线保留检查仍用完整场景。数组比较是完整比较，不能只核验最后一项。平台派生字段出现差异要查明依据，不能为了得到 OK 自动删字段。

恢复时可用 `python scripts/batch_config.py recover /absolute/work/evidence.json`。输入 `expected`、`observed` 是已定位同一目标的最小结果摘要，`state` 使用 processing/saved/confirmed_absent 或其它未定状态。输出分别提示等待已有任务、相同则跳过/不同则重算、确证未落地才在授权范围重试；超时或失败字样本身只提示回读。该工具不会操作浏览器，也不能证明人工提供的状态为真。

## 提交与完成条件

批量值经页面自身解析后仍需相应 Save。检查字段没有被页面重置，等待明确保存结果，重新加载读取服务器值。大批量无需逐元素截图；按保存边界核验关键结果，最后一次完整结构比较。保留版本、变更路径和源单元映射即可恢复；含正文的临时快照不作为公开诊断材料。

能力自动授权等平台派生字段只保留回读现值，不自行指定。批量入口不覆盖的知识导入/Profile/发布状态继续按 workflow.md 处理。
