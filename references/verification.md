# 验收与团队交接

验收基于本场包，不引用 PETOPIA/MIMO 的固定个数或别名。

1. 身份：登录会话是当前成员；目标 Agent、Scenario 的真实 ID 与中文管理名对应。一个 Agent 一个场景的本场目标清楚。
2. 原文：Soul/Agents/正式 LiveScript 保存后回读一致；所有口播行范围排除非空配置备注；脚本变更已刷新引用。中文译本仅审核。
3. 媒体：模板知识文件数量/类别及处理状态正确；实际数字人媒体登记单列确认状态。知识导入不证明可播放。
4. 节目：稳定单元与实际元素映射、完整顺序、源、范围、别名、结束条件、切换、口型、评论开关、时间、配额、循环边界均与包一致。类型修改后检查是否被重置。
5. 互动：两表 ID 关联、规则/动作数量、启用状态、具体规则在兜底前、语言/提示/模板及适用字段逐项一致；无规则不创假条目，单规则不补另一条。
6. 状态：逐板块 Save 后重新打开/刷新读取，所有成功组及失败组分别记录；active 的 revision 与新会话生效范围清楚。

默认在回复记录结果；只有用户明确要求写回包时才在现有媒体映射尾部追加并同步译本。包外持久进度按 workflow.md。检查源文件字节指纹不变，远端正文另作实际比较：

| Block | Source reference / SHA-256 | Expected | Readback | State / evidence |
|---|---|---|---|---|

这是一份结果摘要，不是第二份配置；Expected 引用包内位置，差异才写具体值。记录实际时间及 ID，脱敏，不保存卡密、Cookie。中文译本同步自然语言，正式语言和机器标识不翻译。

批量路径同时检查无关字段/旧 ID 保留、完整数组顺序、明确删除范围与脚本派生引用。`batch_config.py compare` 可辅助比较；OK 只证明提交给工具的预期与回读范围一致，不证明快照来自服务器或未检查字段正确。人工仍须核对当前目标与读取来源。

效率记录复用执行事实：提交/保存次数、针对性重试次数、浏览器/工具往返及人工介入次数；没有计数证据就写未记录。目标是将逐项目写入缩减为按保存组批量提交，校验仍覆盖全部项目。网络和知识处理耗时波动，不承诺固定分钟数。

**分开交付四种结论：**本地结构通过、配置保存回读通过、规则预览结果、实播结果。只有实际执行才能写通过，未执行写未执行。

若用户授权预览：111/1111/hi111/普通评论分别记录实际命中。Deterministic preview 不含模型/媒体；Real LLM/OpenFM; no playback 使用模拟外部结果，不证明切换或原视频播放。若用户授权实播，再观察回复语言、真实模板切换及 Brain 完成事件；不能启动生产会话作为默认验收步骤。

同窗恢复、只在点播视频期间停表、接收请求数与实际执行数、精确匹配均单列实播项。template.sent 不等于 programme.video.ended；后者需当前元素及播放实例匹配。没有这些证据不说玩法已兑现。
